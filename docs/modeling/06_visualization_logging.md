# 06 — 진단 시각화 자동 저장 (실험별 이미지 관리)

## 0. 문제 제기

성능 지표(F1·FAR)가 좋아도 그것만으로는 충분하지 않습니다. 실제 의미는 **시각화에서 확인될 때** 생깁니다. 즉,

- 탐지하고자 하는 구간(실제 이상)에서는 AutoEncoder가 동작(복원오차가 임계치를 초과)하고,
- 탐지를 원하지 않는 구간(정상 운전·기동 스파이크)에서는 동작하지 않는 것이

그래프로 보여야 비로소 모델이 의도대로 작동한다고 말할 수 있습니다. 따라서 이미지 저장은 선택이 아니라 평가의 일부입니다.

문제는 **조정해야 할 옵션이 많아**(임계치 정책, σ 레벨, 집계 방식, 피처 구성, 도메인별 설정 등), 그 조합마다 생성되는 수많은 이미지를 하나하나 수작업으로 저장·정리하기 어렵다는 점입니다. 이 문서는 그 관리 부담을 없애는 방법을 정의합니다.

---

## 1. 핵심 아이디어 — 이미지를 run_id에 묶는다

[05](05_reproducibility_implementation.md)에서 도입한 `run_id`를 시각화에도 그대로 사용합니다. 모든 진단 그래프를 실험 보존본 폴더 안에 자동 저장합니다.

```
models/runs/<run_id>/
  motor_model.keras  ...  run_meta.json
  figures/
    motor__mse_timeline.png        # 도메인별 복원오차 + 임계치 + 라벨/기동 음영
    motor__error_hist.png          # 학습 오차 분포(log y) + 임계치 선
    motor__loss_curve.png          # train/val loss
    hydraulic__mse_timeline.png
    ...
    _contact_sheet.png             # 위 그래프 전부를 한 장에 모은 대조표
    index.html                     # 한 파일로 모든 그래프를 한눈에
```

이렇게 하면 관리 부담이 사라집니다.

- **자동 분류**: 이미지가 실험(run_id)별 폴더에 자동 적재되므로 수동 정리가 불필요합니다.
- **결정적 파일명**: `<도메인>__<종류>.png`로 고정해, 옵션을 바꾼 두 run의 같은 이름 파일을 나란히 열면 즉시 비교됩니다.
- **한 번에 보기**: run마다 `_contact_sheet.png`(또는 `index.html`)로 모든 그래프를 한 화면에 모읍니다. 폴더를 뒤질 필요가 없습니다.

## 2. 어떤 그래프가 필요한가

핵심은 "원하는 곳에서 동작, 원하지 않는 곳에서 비동작"을 한 장에서 보이는 것입니다.

### 2-1. MSE 타임라인 (가장 중요)

도메인별 복원오차(MSE)를 시간축으로 그리고, 다음을 겹쳐 표시합니다.

- 임계치 3선(주의 μ+2σ / 경고 μ+3σ / 심각 μ+6σ)
- 실제 이상 라벨(`anomaly_label==1`) 구간 음영 — 여기서 오차가 임계치를 넘어야 "원하는 동작"
- 기동 구간(`is_startup_phase==1`) 음영 — 여기서 오차가 임계치 아래여야 "원하지 않는 비동작"(startup gating 효과)

이 한 장으로 판단합니다. 이상 음영에서 곡선이 솟고, 기동 음영에서 잠잠하면 모델이 의도대로 동작하는 것입니다.

### 2-2. 오차 분포 히스토그램 (log y)

학습 정상 데이터의 MSE 분포에 임계치 선을 얹습니다. 분포가 한쪽으로 긴 꼬리인지(정규분포 가정 위반 여부, [03 §2](03_threshold_methodology.md))를 눈으로 확인하고, percentile 전환의 근거를 시각적으로 확보합니다.

### 2-3. 학습 곡선 (train/val loss)

과적합(훈련 데이터에만 지나치게 맞춰져 처음 보는 데이터에서는 성능이 떨어지는 현상) 여부를 확인합니다. 두 곡선이 겹치면 처음 보는 데이터에도 잘 들어맞는다(일반화가 양호하다)는 뜻입니다(현재 약 20 epoch 수렴).

### 2-4. (선택) 피처별 기여 / per-feature 오차

알람이 떴을 때 어느 센서가 임계치를 넘었는지 보여주어, RCA(근본 원인 분석 — 어느 부위·센서가 원인인지 짚어내는 것) 해석과 일치하는지 점검합니다.

## 3. 관리 메커니즘 정리

| 부담 | 해소 방법 |
|---|---|
| 이미지가 너무 많다 | run_id 폴더로 자동 분류. 한 실험 = 한 폴더 |
| 어떤 옵션의 결과인지 모른다 | run_meta.json에 phase·git_sha 기록, 폴더명에 phase 라벨 |
| 폴더를 일일이 열어야 한다 | run마다 `_contact_sheet.png` / `index.html`로 한 번에 |
| 두 옵션을 비교하기 어렵다 | 결정적 파일명 → 두 run의 같은 파일명을 나란히 비교 |
| 저장을 깜빡한다 | 평가 스크립트가 자동 저장(수작업 save 제거) |

| 검증 질문 | 그래프에서 보는 법 |
|---|---|
| 기동 스파이크가 threshold를 부풀렸는가 | 시계열의 기동 음영(회색) + 실선(실제 임계치)과 점선("기동 제외 시 임계치")의 간격. 간격이 크면 기동 샘플이 threshold를 끌어올린 것 |

연동 지점
- 학습 시점(train.py, 구현됨): loss curve + MSE 진단(기동 음영·기동 제외 임계치 병기)을 `models/runs/<run_id>/figures/`에 저장. 학습 데이터엔 이상 라벨이 없어 anomaly 음영은 비움.
- 평가 시점(evaluate_test_metrics.py, 구현됨): 도메인별 MSE 타임라인에 `anomaly_label` 음영 + 학습/평가 경계선을 그려 같은 run의 `figures/`(LATEST_RUN.txt로 조회)에 `<도메인>__eval_timeline.png`로 합류. 데이터가 월1(정상)→월2(drift)→월3(이상)이라, 경계선 이후 이상 음영에서 MSE가 임계선을 돌파하는지로 "이상 구간부터 탐지되는가"를 확인. 평가 데이터엔 이상값이 섞여 있어 '기동 제외 임계치' 보조선은 `show_excl_startup=False`로 끔.

설계 원칙
- 그래프는 [01 §2](01_experiment_protocol.md)의 보존본 폴더에 저장하므로 모델과 이미지가 항상 한 묶음으로 보존됩니다.
- 기동 마스크는 AE 입력에 남은 운전 맥락 피처에서 도출합니다(`is_startup_phase` 우선, 없으면 `minutes_since_startup<=5` 근사).
- matplotlib 부재 시 import 실패를 흡수해 학습 자체는 진행됩니다. 대량 렌더는 무거운 작업이므로 학습 스크립트와 함께 사용자가 직접 실행합니다.

## 5. 기대 효과

- 옵션을 바꿀 때마다 그 결과 이미지가 실험별로 자동 정리되어, "수많은 이미지를 수작업 관리"하는 부담이 사라집니다.
- 성능 수치와 시각 증거가 같은 run_id로 묶여, "지표도 좋고 그래프도 의도대로"를 한 번에 입증할 수 있습니다.
- 포트폴리오·발표에서 특정 run의 contact sheet 한 장으로 모델 동작을 설명할 수 있습니다.
