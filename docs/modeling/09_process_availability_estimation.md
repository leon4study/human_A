# 09 — 공정률(가동률)·다운타임 감소 산정 방법론 — 예지보전 도입 효과 추정

> 목적: 운영 KPI "공정률"을 *정의·산정식·근거*까지 갖춰 **설계**한다. 측정된 도입 결과가 아니라, **검증된 모델 성능(lead-time·FAR)에서 명시적 가정으로 환산한 추정**이다. 면접 "이 수치 어떻게 산정?"에 따박따박 답하기 위한 SSOT.
> 상태: **방법론 설계(추정)** — 실농가·실배포 검증 전. [08 §4 OEE](08_domain_metrics_validation.md)의 가용성 항을 구체화.
> ⚠ P-002: 합성 시나리오로 실제 산출·수치 확정 전까지 포트폴리오 본문에 *맨 수치* 노출 금지. 노출 시 반드시 "추정 · 산정방법 설계"로 라벨.

## 0. 정의 (매핑)
- 본 프로젝트 **공정률 ≡ 설비 가동률(Availability)** = OEE 3요소(가용성×성능×품질) 중 가용성 항.
  ```
  가동률 = 실가동시간 / 계획가동시간 = (계획가동 − 총다운타임) / 계획가동
  ```
- 출처: Nakajima(1988) *Introduction to TPM* — OEE·가용성 원전 / SEMI E10 — 설비 신뢰성·가용성·유지보수성 표준.
- (대안 매핑: 성능·품질까지 포함한 OEE 전체로 확장 가능. 우선 다운타임에 직접 반응하는 가용성으로 정의 — 필요시 조정.)

## 1. 무엇이 공정률을 올리나 (검증값에만 연결)
추정의 출발점은 **검증된 모델 우위 2가지뿐.** 여기서 벗어난 가정은 두지 않는다.
1. **조기 감지(lead-time 35.9h)** → 돌발 정지 전 막힘 포착 → *계획 정비*로 전환 → 다운타임↓.
2. **헛알람 감소(FAR 5%→1.4%, ~3.6배↓)** → 불필요 정지·점검↓ → 비가동↓.
- ※ "막힘을 더 많이 잡아서"는 **가정에 넣지 않음** — 단일센서 baseline도 심한 막힘 6/6 검출([08 §2](08_domain_metrics_validation.md)). 우위 = '더 많이'가 아니라 **'더 일찍 · 헛알람 적게'**.

## 1-2. 산업 벤치마크 (예지보전 도입 효과 · 출처 확보, 2026-06)
| 지표 | 산업 벤치마크 | 출처 |
|---|---|---|
| 다운타임 감소 | **30~50% ↓** | McKinsey · Deloitte (PdM) |
| 설비 가동률/가동시간 | **+10~20%** | Deloitte |
| 유지보수 비용 | 18~40% ↓ | McKinsey · Deloitte |
| OEE | world-class **85%**(가용성≥90%·성능≥95%·품질≥99.9%) vs 산업평균 **55~60%** | Nakajima(TPM 원전) · Evocon · OEE.com |

**우리 시스템과의 연결 (메커니즘 일치)**: PdM의 다운타임↓·가동률↑는 ① 조기 감지로 *돌발→계획 정비* 전환 ② 오탐↓로 *불필요 정지* 감소에서 나온다 — 본 시스템이 **검증값(35.9h 조기감지 · FAR 5%→1.4%)**으로 확보한 바로 그 메커니즘. → 산업 PdM 효과 범위로 **추정 적용**.

**추정 발화 (라벨 필수)**: "예지보전 도입 시 산업 PdM 벤치마크 기준 **다운타임 30~50%↓ · 가동률 10~20%↑** (추정 — 합성·미배포라 실측 아님; 본 시스템의 검증 메커니즘이 벤치마크에 부합)." ※ OEE "78→85%"(강사 제시)는 *목표값*이라 그대로 쓰지 않고, 위 산업 범위로 대체.

## 2. 산정 절차 (합성 시나리오 + 명시 가정)
1. 동일 EVAL 시나리오에 두 정책: A=단일센서 baseline, B=AE.
2. 정책별 **총다운타임 = 돌발 + 계획 + 헛알람정지**
   - 돌발 = (조기감지 실패 막힘 수) × D_u(돌발 정지시간)
   - 계획 = (조기감지 성공 막힘 수) × D_p(계획 정비시간),  **D_p ≪ D_u**
   - 헛알람 = FAR × 평가구간 × D_f(점검 정지시간)
3. **두 출력(같은 계산):**
   - **다운타임 감소율(%)** = (총다운타임_A − 총다운타임_B) / 총다운타임_A × 100 — 직관적 헤드라인 "도입 → 다운타임 N% 감소"
   - **가동률 향상(%p)** = 가동률_B − 가동률_A,  가동률 = (계획가동 − 총다운타임)/계획가동 — OEE 표준 프레임
   - 둘은 같은 다운타임 입력에서 나오는 두 시각. 헤드라인은 다운타임 감소, 표준 지표는 가동률.
4. **가정 표(출처·근거 필수)**: 막힘 빈도 · D_u · D_p · D_f — 산업자료/시뮬 가정 명시(없으면 '가정'으로 표기). ← repo 최대 약점 "출처 0건" 보강 지점.

## 3. 정직성 (CEDR)
- 라벨: **"산정 방법 설계 + 합성 시나리오 추정"**. 측정된 실배포 결과 아님.
- 모델 우위(lead-time·FAR)는 검증값(status.md · [08 §2](08_domain_metrics_validation.md)), **가동률 환산만 추정**.
- 절대값이 아니라 *정의·가정·출처의 타당성*으로 평가받는 지표.

## 4. 면접 방어 ("이 공정률 어떻게 구했어요?")
1. 공정률=가동률로 정의(OEE 가용성 항), 표준 출처 제시.
2. 향상 출처 = 검증된 lead-time·FAR (지어낸 '더 많이 잡음' 아님).
3. 명시 가정으로 환산 → 합성 시나리오 기반 → 실농가 미검증, 솔직히.
→ 핵심 어필: *"측정은 못 했지만, 현업이 인정하는 지표를 정의하고 검증값에서 투명하게 환산했다."*
