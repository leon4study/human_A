# 1. ADR을 사용해 결정을 기록한다

Date: 2026-04-23

## Status

Accepted

## Context

이 프로젝트는 모델 설계·도메인 분리·임계값 전략 등에서 여러 중요한 기술 결정을 내렸다.
그 결정의 배경과 근거가 코드와 산발적인 문서에 흩어져 있어, 새로 합류한 사람이 "왜 이렇게
되어 있는가"를 파악하기 어렵다. 결정의 맥락이 사라지면 같은 논의를 반복하거나, 이유가 있던
설계를 무심코 되돌리게 된다.

## Decision

Michael Nygard가 제안한 Architecture Decision Record(ADR) 형식으로 중요한 결정을 기록한다.

- 각 결정은 `docs/adr/` 아래 번호가 붙은 개별 파일로 남긴다.
- 이전 결정은 고쳐 쓰지 않는다. 결정이 바뀌면 새 ADR이 이전 것을 대체한다.

## Consequences

- 결정의 "왜"가 한곳에 모여 신규 합류자의 온보딩이 쉬워진다.
- 모델 실험의 반복 기록은 [.claude/MODEL_CHANGELOG.md](../../.claude/MODEL_CHANGELOG.md)가,
  중요한 설계 결정의 확정 기록은 ADR이 담당하도록 역할을 나눈다.
- ADR 작성이 약간의 추가 비용이지만, 결정의 추적성을 얻는다.
