# 3. 농장을 4개 도메인으로 나눠 도메인별 AE를 학습한다

Date: 2026-04-23

## Status

Accepted

## Context

설비 전체 센서를 하나의 AutoEncoder로 학습하면, 서로 무관한 신호들이 한 잠재공간에 섞여
어느 부위가 이상인지 가리키지 못한다. 또한 한 부위의 정상 변동이 다른 부위의 이상을 가린다.
근본 원인(RCA)을 함께 제공하려면 이상이 "어디"에서 났는지 분리되어야 한다.

## Decision

흐름 경로 단계 × 고장 종류를 기준으로 농장을 4개 도메인으로 나누고, 도메인별 AE를 학습한다.

| 도메인 | 감시 대상 | 주요 이상 |
|---|---|---|
| `motor` | 모터 전력·전류·온도·RPM·베어링 진동 | 베어링 마모, 과부하, 권선 절연 열화 |
| `hydraulic` | 토출/흡입 압력·유량·필터 차압·공급 균형 | 배관 막힘, 누수, 밸브 이상 |
| `nutrient` | 양액 EC/pH·목표 오차·염류 축적 | 비율 오류, 양액 막힘, 센서 드리프트 |
| `zone_drip` | 구역 배지 수분/EC·구역별 분산 | 점적 노즐 막힘, 구역 관수 불균일, 배지 염류 |

## Consequences

- 알람이 도메인 단위로 떠 RCA가 가능해진다(어느 부위인지 즉시 지목).
- 전체 알람은 도메인별 알람의 최댓값으로 통합하되, 오탐이 잦은 `nutrient`는 통합 투표에서
  제외한다(ADR 0005).
- 도메인 경계 설정이 설계 판단이 된다. 예: 공급 균형 지표(supply balance)는 흐름 지표이므로
  `zone_drip`이 아니라 `hydraulic`에 둔다(Phase G에서 이동). 도메인 정의는
  [DOMAIN_DESIGN.md](../DOMAIN_DESIGN.md) 참조.
- 도메인마다 별도 학습·임계값·스케일러·SHAP 산출물이 생긴다(`models/<domain>_*`).
